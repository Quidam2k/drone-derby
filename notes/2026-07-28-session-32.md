# Session 32 — 2026-07-28 — Phase 32: respawn facing

Third rules-parity phase shipped: a destroyed robot's player chooses its
re-entry facing (1994 rule), replacing `respawnRobots`' hard-coded `'N'`.

## Shape (Todd's decisions, from scoping)

- Choice made **while programming the next turn** — you see where you
  re-entered before aiming, and it rides the program submission so async
  play never blocks.
- Robot respawns end-of-turn-N facing N (event untouched); engine applies
  the choice at the **start of turn N+1** right after `turn-started`, as a
  plain `robot-rotated` — every consumer already handles it, zero new
  presentation work.
- The board robot **turns live** as the picker is toggled (visual-only
  override of the facing passed to BoardView).

## What changed

- `types.ts`: `RobotState.justRespawned?: boolean` — engine permission
  gate AND the UI's show-the-picker trigger; optional so stored Convex
  states stay valid.
- `execute.ts`: `executeTurn(state, programs, seed, respawnFacing?)`;
  `applyRespawnFacing` right after the turn-started emit — active +
  flagged + valid + differing → set facing, emit `robot-rotated`; flag
  deleted for every flagged robot regardless. Unflagged players' choices
  ignored (server-side legitimacy for free).
- `preview.ts`: `previewProgram(..., respawnFacing?: Direction)` so the
  ghost aims with the picker (rotate lands before register 1, survives
  the truncation cut).
- `ProgrammingView`: "Back in play — face:" arrow row
  (`respawn-facing-{N,E,S,W}` testids) above the registers when flagged;
  `liveVisual` memo patches the robot's facing for BoardView +
  PlayerStrip + ghost base; `onSubmit(program, taunt?, respawnFacing?)`.
  CSS `.respawn-facing-row` in index.css (modeled on tool-option-row).
- `gameStore`: `pendingFacings` per seat, passed as executeTurn's 4th
  arg when the last seat submits; cleared everywhere the others are.
- Online: `games.submitProgram` args + `submissions` schema gained
  `respawnFacing` (N/E/S/W literal union); execute path builds the
  `Record<PlayerId, Direction>` from submissions. No server AFK path
  exists yet; absent → default N.
