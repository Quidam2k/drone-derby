# 2026-07-26 — Phase 3D-1: `Board3D` spike

Todd's direction: proceed as if we're going to fully animated 3D robots
and boards. This phase builds the spike that answers the three questions
that could kill that direction, deleting nothing.

## What was built

| Thing | Where |
|---|---|
| `three` + `@types/three`, reached only via `await import('./scene')` | `package.json` |
| `--export-glb` mode reusing `build(seat)` verbatim | `scripts/blender/robots.py`, `scripts/render-robots.mjs --glb` |
| Four static chassis meshes | `public/models/robot-{0..3}.glb` |
| WebGL renderer with the DOM `Board`'s exact props | `src/components/board3d/` |
| `?render=3d` flag, one line per call site | ProgrammingView, ReplayPlayer, OnlineGameScreen |
| `glb` in the precache glob | `vite.config.ts` |
| No-canvas rule rescoped to editor + thumbnails | `CLAUDE.md` |

Untouched: engine, EventLog, Convex, `visualState.ts`, `Board.tsx`,
`Tile.tsx`, `BoardThumb.tsx`, `EditorBoard.tsx`.

`Board3D`'s props are `Parameters<typeof Board>[0]` — derived from the DOM
board rather than copied, so the two cannot drift without a typecheck
failure, and `Board.tsx` still needed no edit.

## Measured (production build, `npm run preview`)

- **Main JS** 113.88 → **114.90 KB gz** (+1.0 KB: the React shell + flag).
- **Lazy chunk** `scene-*.js` = **171.19 KB gz** (660 KB raw). Verified
  lazy: lobby, `#/editor`, `#/rules` and the setup screen fetch neither
  it nor any `.glb`, with the flag on. No `modulepreload` in index.html.
  → **the webgl-analysis note's 38 KB three.js figure was ~4.5x too low.**
- **Precache** 709 KiB → **2126 KiB / 40 entries** — the scene chunk plus
  770 KB of uncompressed `.glb`. This is the direction's real cost; every
  offline install pays it. Draco/meshopt is the untried lever.
- **Frame time**, Grand Circuit (composed 12x17), 4 robots, replay
  running, CDP `Emulation.setCPUThrottlingRate`:

  | throttle | busy-loop calibration | median | p95 | worst | >20 ms |
  |---|---|---|---|---|---|
  | 1x | 9.2 ms | 16.7 | 16.7 | 16.9 | 0 |
  | 4x | 54.6 ms | 16.7 | 16.7 | 16.8 | 0 |
  | 6x | 52.6 ms | 16.7 | 16.8 | 33.4 | 4 / 237 |

  Spin Cycle (12x10) is identical. The calibration column is the proof
  the throttle was actually applied — measuring rAF deltas alone would
  have read 60 fps whether or not throttling worked, which is exactly the
  trap the analysis note fell into by not measuring at all.
  **Caveat: CDP throttles the CPU, not the GPU.** A real low-end phone is
  still the honest test; this rules out a CPU-bound failure only.
- **Correctness.** Stepped one whole turn cursor-by-cursor (99 steps, 25
  of which moved a robot), reading rig world positions back out of the
  scene: zero off-grid, out-of-bounds, diagonal, or moved-on-a-non-move.
- **Console.** Zero errors and zero warnings across a full 4-player game,
  replay, and scene unmount.

## Two things the first pass got wrong

1. **Canvas sizing.** Sizing the canvas by board aspect ate the entire
   `100dvh - 12rem` height budget, so the hand and registers fell below
   the fold — the DOM board caps its tiles at 52px and never does that.
   Fixed by sizing off `tileFit()` itself: width = `tile * board.width`,
   height = `tile * (height * sin(elev) + 1.5)`. Tilting costs the board
   depth, so the 3D board needs *less* height than the DOM grid.
2. **FOV 34 was too wide.** On the 17-row composed board the near rank
   rendered twice the size of the far one and the top was unreadable.
   FOV 20 ("orthographic-ish", as planned) keeps tiles roughly uniform
   while still giving the chassis perspective to sit in.

Also replaced: checkpoint/spawn numbers were pips in a row, which read as
a face rather than a number. They're canvas-texture digits now, matching
what the DOM board draws.

## Deliberately absent

3D-4 owns full event parity. Missing: speech bubbles, bump flash,
fall/respawn animation, checkpoint pop. Laser beams and damage flashes
are in so the look comparison is fair. `settled()` never returns true on
a board with conveyors — the belts keep the rAF loop alive by design.
