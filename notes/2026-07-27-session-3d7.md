## Decisions

- **Precedence is the spec.** `?render=dom` → capability → `?render=3d` →
  stored preference. Capability beats intent deliberately: an explicit
  `?render=3d` on a machine with no WebGL2 still gets the DOM board, because
  forcing 3D there is exactly the blank canvas this phase exists to stop.
- **The failure flag is per page load.** A driver hiccup must not permanently
  downgrade a player who chose 3D, and must not overwrite their stored
  preference — so `markRenderer3dFailed()` is a module-level boolean, and the
  disabled 3D button says "reload to try again".
- **↺ does not reset the renderer.** It is a camera control.
- **Disabled with a reason, not hidden.** Three reasons, three different
  hover texts: no WebGL2, scene failed this load, forced off by `?render=dom`.
- **Top-left, outside `.board-viewport`.** Opposite corner to the camera strip
  (measured at 375 px: toggle x 28–88, camera strip x 167–347, no overlap), and
  outside the box that scrolls on a panned composed board.
- Cosmetic, noted not fixed: on the **DOM** board the toggle overlays the
  top-left tile. Same trade the camera strip already makes on the right; moving
  it above the board risks colliding with the screen header on tight layouts.

## Traps hit (worth remembering)

- **`page.addInitScript` on the MCP page object did nothing**; the
  context-level `page.context().addInitScript(...)` + a new page worked. Every
  `browser_run_code_unsafe` call is a fresh sandbox, so `globalThis` does not
  survive between calls — re-find the context with
  `page.context().browser().contexts()`.
- **The service worker serves the precache out of reach of `page.route`.** The
  first attempt to fail the scene chunk silently succeeded in loading it from
  cache. Aborting `sw.js`/`registerSW.js` too is what made fault injection
  real.
- A `page.goto` that only changes the hash does **not** reload — the same trap
  3D-3 lost an hour to. Use `location.reload()` or change the query string.
- Placed hand cards stay in the DOM as `disabled`, so
  `[data-testid^="card-"]:not([disabled])` is the selector for "next card".
