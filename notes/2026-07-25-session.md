### Cross-phase decision confirmed by fix #3

`cleanUpCards` recomputes `stillLocked` from the **current**
`lockedRegisters`. So when phase 30 (repair) or 33 (power-down) lowers
damage and unlocks a register, the freed card returns to the discard pile
for free — **provided the repair/power-down step runs before
`cleanUpCards`**. That ordering is load-bearing, not incidental.

## Phase 29 — robot art baker, chassis 0 — BUILT, awaiting gate

`scripts/bake-robots.mjs` (zero-dep Node ESM) → `npm run art` →
`src/components/board/robotArt.generated.tsx`. 3D geometry, orthographic
camera pitched **45°** off vertical with yaw 0 (so the existing CSS
`rotate()` still reads as turning), backface cull, painter's sort, flat
Lambert. 66 faces modelled, 32 visible. Chassis 0 = tracked scout: two
tapered tread pods, bevelled hull, rear-set canopy with a dark screen
cap, sloped forward deck with a glowing nose pad, rear heat sink.

### The camera angle is the whole ballgame

First bake used 26° off vertical — near top-down — and Todd's reaction
was "those are flat 2D." He was right: height only contributes
sin(PITCH) to the silhouette, so at 26° every vertical face projects
about a pixel and genuinely-3D geometry bakes out looking flat. Fixed by
**two** changes that only work together: pitch → 45°, and give the
chassis real height (it was a pancake, 0.49 tall vs 0.94 wide; now 0.80).

Knock-on: a taller silhouette at a steeper pitch spends more viewBox on
height, so auto-fit shrinks the footprint. Compensated in CSS, not in the
bake — `.robot-body.baked` is 88% of the tile vs the flat sprites' 72%,
which puts the on-board footprint back on par (~33px of a 52px tile).

Recolorable as required: each body face emits a *pair* of paths,
`fill="var(--seat)"` + a `#000`/`#fff` overlay at the computed opacity.
`--seat` is set on the rotating `.robot-body` wrapper and inherits into
the inline SVG. `usesBakedChassis(seat)` in `sprites.tsx` is the single
predicate for both the `baked` CSS class and the sprite branch — phase 34
flips that one function.

### What the first bake got wrong (matters for phase 34)

- Ambient-dominant Lambert gives every +z deck the same value, so the
  hull and canopy merged into one flat blob. Needed a per-material
  `tint` multiplier *plus* a dark cap on the canopy — two seat-coloured
  decks never separate on lighting alone.
- A recessed dark slot across the back reads as a mouth, and a mouth
  flips which end looks like the front. Made it a raised bar instead.
- Detail buried inside a neighbouring part is silently wasted (the first
  heat sink sat inside the canopy's rear overhang). The visible-face
  count in the baker's log is the tell.
- Facing cues live on **top** faces — a legacy of the flat 26° bake, but
  still right at 45°, and the nose pad survives every rotation.
- Board.tsx must not set an inline `background` for baked seats; inline
  beats the `.robot-body.baked` rule that clears it.
