# Session 33 — 2026-07-28 — Phase 33: power-down

Fourth rules-parity phase shipped: the 1994 power-down. Announce while
programming turn N; during turn N+1 the robot is down — all damage
removed at the start of that turn, no registers, no laser — while
belts/gears/pushes/lasers still act on it. Counterweight to the 1-point
repair economy. Remaining parity gap: pushers (Phase 34).

## Shape (Todd's decisions, from scoping)

- **One-tap turn**: the powered-down player still submits — a single
  "Stay powered down / Wake up" choice riding an all-null program — so
  the async await/nudge loop is untouched (`waitingOnNames` unchanged).
- Board-faithful multi-turn power-down; **any** robot may announce;
  destruction ends the power-down (respawn as normal, may re-announce —
  composes with Phase 32's facing picker, both ride the same submission).
- Phase-32 pattern: `RobotState.poweredDown?` is both the engine's
  permission gate and the UI trigger.

## What changed

- `execute.ts`: 4th arg is now `TurnChoices = { respawnFacing?,
  powerDown?: PlayerId[] }` — engine-internal breaking change, all call
  sites updated (gameStore, convex/games, preview, respawnFacing tests).
  `powerDown` names announcers OR stay-downs; the flag disambiguates in
  `applyPowerDownChoices`, which runs **before respawnRobots** so a
  robot destroyed this turn lands in neither branch (announcement void;
  may re-announce next turn). `prepareTurn` skips powered-down robots;
  `powerDownRepair` (right after turn-started, beside
  `applyRespawnFacing`) clears all damage via one `repair` event and
  releases locked registers (`register-unlocked`, cards pushed straight
  to the discard pile — they're outside cleanUpCards' effective sweep);
  `fireRobotLasers` skips them (still hit); `killRobot` deletes the
  flag. `deck.ts` `dealHands` skips them (no cards while down; waking
  deals 9 − damage — damage taken while down sticks).
- `events.ts`: + `robot-powered-down` / `robot-powered-up` (extended,
  not reshaped). `preview.ts`: powered-down robot previews `[]`.
- **Deviation from plan**: dropped the second flag `powerDownAnnounced`
  — the plan's own execute spec never set it (choices flip straight
  into `poweredDown` at end of turn); it would have been a dead field
  in stored states. One flag does both jobs.
- Presentation: `RobotVisual.poweredDown` (folded from the two events,
  cleared on `robot-respawned`, seeded by `initialVisual`); captions
  "powers down — all systems off" / "powers back up" (500 ms); audio
  borrows 'lock'/'respawn'; director interest 0.45; 3D rig
  `setPoweredDown` kills emissives (damage-flash restore respects it);
  DOM `.robot.powered-down .robot-body` opacity .55 + grayscale.
- UI: footer "⏻ Power down next turn" toggle;
  `onSubmit(program, taunt?, respawnFacing?, powerDown?)`; one-tap
  screen when `robot.poweredDown` (testids `powered-down-choice`,
  `stay-powered-down`, `wake-up`). Hot-seat: gameStore
  `pendingPowerDown: PlayerId[]`. Online: `submitProgram` arg +
  submissions column `powerDown: v.optional(v.boolean())`; server
  rebuild already maps the all-null program through.
